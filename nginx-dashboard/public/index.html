Regles d'analyse

        
      

      
Ce que chaque regle detecte, pourquoi, et comment l activer ou la desactiver — sans redemarrer l agent.


      
Agent injoignable — impossible d afficher ou de modifier les regles pour le moment.


      

        
        
        
        
      


      
      

        

          Comment le moteur traite ces regles
          

        

        

        

          
Par vhost, dans le fichier de conf (avant le bloc server{} ou a l interieur) :

          
# nginx-control-analyze: off
# nginx-control-analyze-ignore-rules: 1, 2, 4
# nginx-control-analyze-no-remediation: on
# nginx-control-analyze-rule-1-paths-ignore: /wp-json/wpa/v1/verify-session,/autre/*

          
(identifiants ci-dessus, pris en compte par l agent dans la minute qui suit — no-remediation garde les alertes mais empeche le blocage automatique "Blocklist IP" pour ce vhost ; paths-ignore retire ces chemins (sans query string, "*" final = prefixe) du comptage de la regle indiquee, pour ce vhost seulement)

        

      


      
      

        
Vos regles : un critere (chemin, agent, code, methode), un seuil sur une fenetre glissante, et au choix un blocage automatique. Le formulaire genere le YAML pour vous.

        

          
          
          
          
          
          
        

        

        

        

        
Enregistrer depuis le formulaire regenere le YAML (les commentaires saisis a la main en mode avance ne sont pas conserves).

      


      
      

        
Modeles prets a l'emploi par application. « Ajouter » les copie dans Mes regles (un id libre est attribue) ; ajustez-les puis enregistrez.

        

      


      
      

        

          Definissez vos propres regles au format YAML — un principe proche des scenarios CrowdSec : un identifiant (>= 100), un critere (chemin, agent, code de statut) et un seuil sur une fenetre glissante.
        

        
        

        

          
          
        

        
Ce texte remplace l'ensemble de vos regles personnalisees (c'est le format de stockage ; le formulaire en est une vue).

Bannir une adresse

        
      

      

        Identifiants machine non configures — le bannissement et les listes blanches necessitent
        CROWDSEC_MACHINE_ID / CROWDSEC_MACHINE_PASSWORD, distincts de la cle de bouncer.
        A creer une fois via cscli machines add nginx-dashboard --password <phrase-secrete> sur la machine CrowdSec — jamais --auto, qui genere un mot de passe que rien ne vous montre ensuite. Redemarrez le dashboard apres avoir renseigne les deux variables : elles ne sont lues qu au demarrage.

        Lecture seule : confirme absent du schema publie par la LAPI de CrowdSec — seul
        GET existe sur /allowlists. Une liste se cree et se modifie via
        cscli allowlists ... sur l hote CrowdSec, ou la Console si elle y est geree ;
        le dashboard affiche son contenu, il ne peut pas l ecrire.
